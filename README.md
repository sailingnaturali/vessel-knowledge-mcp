# vessel-knowledge-mcp

MCP server that turns equipment manuals into a private markdown vault of equipment
cards and exposes per-reading alarm-zone lookups and notification explanations to AI
agents via four tools.

**Two halves:**
- **Runtime MCP** — loads a markdown vault of equipment cards, exposes `explain_notification`,
  `get_equipment`, `find_equipment`, `check_reading`.
- **Build-time CLI** (`vessel-knowledge`) — ingests source PDFs via the Claude API, builds
  a full-text INDEX.md, and pushes zone metadata into SignalK.

**Two-fact split:** Equipment cards live in a **private vault repo** (generic per-make/model
facts extracted from manuals). The mapping from SignalK path prefixes to equipment models
lives in a **vessel-profile bindings file** (`bindings.json`). The engine ships no content
— you bring both.

## Proactive-alarm model

Cards encode per-measurement zone bands (normal / warn / alarm / emergency) in **SignalK
canonical SI units** (Kelvin for temperature, Pascal for pressure, m/s for speed, ratio for
dimensionless). `vessel-knowledge zones` generates a SignalK `meta` delta from those bands.
When SignalK ingests that delta it raises notifications autonomously — no polling required.
`explain_notification` then turns a live notification path+state into a plain-language
equipment explanation.

**Zone bounds are stored in canonical SI units (Kelvin, Pascal, m/s, ratio). Not Celsius,
not bar, not knots.** `display_units` is metadata only, for human readability.

## Install

    uv sync                          # runtime only
    uv sync --extra ingest           # + Claude API pipeline

## Run the server

    VESSEL_KNOWLEDGE_VAULT_PATH=/path/to/vault \
    VESSEL_KNOWLEDGE_BINDINGS_PATH=/path/to/bindings.json \
    uv run vessel-knowledge-mcp

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `VESSEL_KNOWLEDGE_VAULT_PATH` | `~/.vessel-knowledge-vault` | Directory containing `equipment/*.md` cards |
| `VESSEL_KNOWLEDGE_BINDINGS_PATH` | — | JSON file mapping SignalK path prefixes to equipment model IDs |

## MCP tools

| Tool | Description |
|---|---|
| `explain_notification` | Explain a SignalK notification: what equipment is on the path, rated zones, current state, and what to check |
| `get_equipment` | Full equipment card — specs, part numbers, service intervals, rated zones |
| `find_equipment` | Resolve a manufacturer/model/alias query to an `equipment_id` |
| `check_reading` | Deterministic in/out-of-range verdict for a value against an equipment's rated zones |

## Build-time CLI

    # Ingest a manual PDF into the vault (requires ANTHROPIC_API_KEY)
    uv run vessel-knowledge ingest manual.pdf --vault /path/to/vault

    # Regenerate INDEX.md listing all cards
    uv run vessel-knowledge index --vault /path/to/vault

    # Push zone metadata to SignalK (generates a meta delta JSON)
    uv run vessel-knowledge zones \
      --vault /path/to/vault \
      --bindings /path/to/bindings.json

## Vault structure

    vault/
      equipment/
        <equipment-id>.md    # one file per make-model
      INDEX.md               # generated by `vessel-knowledge index`

Each card is markdown with YAML frontmatter. See `src/vessel_knowledge_mcp/models.py` for
the full schema (`Equipment`, `Measurement`, `Zone`).
